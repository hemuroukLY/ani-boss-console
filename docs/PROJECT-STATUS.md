# ANI BOSS Console 当前状态

> 本文件是项目当前范围、数据接入状态、主要缺口和简短开发记录的集中入口。产品与接口事实仍以对应 GitNexus 索引为准。

## 当前口径

- 项目：独立 ANI 平台管理端前端；仓库根目录已经代表 BOSS 范围，源码按业务语义命名。
- 产品原型：GitNexus 索引 `产品原型-9.03`；信息架构、菜单、路由和页面交互以该版本为准。
- 后端：独立 ANI 仓库；接口契约与行为以 GitNexus 索引 `ANI` 为准。
- 应用骨架：与 `ani-console` 保持一致，顶部承载一级菜单，左侧承载二级菜单和三级分组。
- UI：Arco Design React 为基础组件库，Tailwind CSS 负责布局，ECharts 负责图表。
- 数据：已建立统一 API 请求入口和平台身份会话；GPU 资源池管理已接入 ANI 实际库存、占用、调度规格目录、GPU 配额和租户资源预留，其余页面仍主要使用前端模型和演示状态。
- 验证：页面与交互默认由项目负责人手动验证；Agent 不主动构建或启动应用。

## 当前模块

### 平台运营总览

- 运营总览：运营指标、告警摘要与待处理事项。
- 资源池与容量态势：区域容量与资源状态。
- GPU 资源池态势：GPU 设备、使用率与状态展示。
- AI 服务运营态势：推理服务指标、趋势和异常服务。
- 知识库运营态势：知识库规模、查询趋势和索引状态。
- 平台告警与待处理：平台告警列表及演示处置状态。

### 租户管理

- 租户列表与租户详情。
- 配额策略列表与详情。
- 租户管理员列表与详情，以及邀请、角色和密码相关弹窗。
- 租户计费与用量列表、详情和账务记录。
- 租户生命周期、身份安全、配额使用与操作历史等详情区域。

### 资源池与基础设施

- 平台资源池总览。
- GPU 资源池管理：展示 ANI 返回的设备库存和占用汇总，支持调度规格目录的查询、新建与删除，以及租户 GPU 配额上限与聚合资源预留的查询、调整和写后刷新；页面读取 `dev_profile` 区分真实 Kubernetes Provider 与本地开发数据，新建规格仅从实际节点标签中选择并限制为后端可映射的整卡、half 或 quarter 策略，聚合预留为 0 时按已落库和实例创建闸门的真实语义展示为“预留上限为 0”；指定物理卡分配、对某张卡执行切分、维护/恢复、平台级调度队列和资源池事件因后端尚无对应接口而不提供模拟操作。
- 节点状态，位于资源池菜单下，包括区域、资源池、健康状态和关键字筛选。
- 存储基础设施，位于基础设施菜单下，展示块、对象、文件和向量存储后端的健康与容量状态、StorageClass 运营和最近平台事件。
- 租户存储配额，位于基础设施菜单下，顶部保留汇总指标，下方由租户热度 TopN、租户存储配额和最近事件三个板块组成。
- 网络基础设施，位于基础设施菜单下，展示 SDN 控制器、出口网关、IPAM、网络组件和 IP 地址池运行状态。
- 镜像仓库运维，位于资源池与基础设施菜单下，包括租户镜像配额、漏洞扫描和垃圾回收三个静态页面；支持配额状态、镜像风险、用途和关键字筛选，后台操作以禁用态保留。

### 运维与可观测

- 平台健康：汇总控制面和数据面组件的正常、降级、异常状态，展示依赖检查并提供指标、日志和 Trace 下钻入口。
- GPU 监控、推理监控和知识库监控：使用统一监控骨架展示领域指标、趋势图和当前关注项。
- 组件指标：支持切换平台组件，展示 P99、错误率、就绪副本、请求量和依赖探测结果。
- 日志与 Trace：提供静态日志组合筛选、调用链样本切换、瀑布图和耗时排行。
- 告警规则、运维 Skills、任务历史和故障处理：原型未接入 Store，当前统一保留优先级与未接入说明，不补造列表、筛选或操作数据。

### 平台计量与结算

- 计量总览：按 GPU-Hours、CPU-Hours、Memory、Storage、Tokens 和 KB Queries 六个原型页签展示本月合计、环比、峰值日、配额使用率、近 7 日趋势与租户用量排行；支持区域和租户关键字筛选，导出操作保持禁用。
- 原型菜单备注写有“七类指标”，但页面线框实际只定义上述六个页签；当前实现以可运行线框为准，待产品口径澄清后再补充。

### 安全审计与合规

- 平台审计日志、API Key 审计、推理调用审计和合规导出与取证：原型均未接入 Store，当前统一使用占位页，不补造审计记录、筛选项或取证向导。

### 平台设置

- 平台登录：接入 ANI 平台管理员账密登录、登录态持久化、Bearer 请求头、401 单飞刷新、受保护路由和退出吊销；开发环境可显式跳过登录以配合 ANI 开发鉴权模式。
- 平台运营账号：展示管理端本地登录身份、角色、状态、MFA 和最近登录信息，支持角色、状态和关键字筛选以及只读详情；账号不属于租户，也不会同步为租户成员。
- 登录与 IdP、会话与安全策略：分别为 P1、P2 预留页，当前统一保留未接入 Store 占位，不展示推测性的配置结构或策略值。

### 平台集成与通知

- 运维 Webhook、企业通知集成和运营系统对接：原型未接入 Store，当前统一使用占位页，不补造订阅、渠道、投递或外部系统数据。

产品原型 `产品原型-9.03` 中 BOSS 端 8 个一级菜单、41 个可点击页面均已形成对应静态路由；后续新增范围仍须先更新并查询产品原型。

## 当前缺口与整理重点

- 当前仅 GPU 资源池管理接入真实 ANI API；其余前端演示数据仍不能作为接口契约依据。
- 管理端已接入平台账密登录与身份会话；Vite 开发服务器通过 `VITE_API_PROXY_TARGET` 配置 `/api` 转发，`.env.development` 当前连接 ANI 开发环境，未配置时回退到 `http://127.0.0.1:8080`。本地 `ANI_AUTH_MODE=dev` 可使用开发跳过登录；生产部署仍需在 Web Server 或网关配置同源 `/api` 转发。ANI 当前 scope 守卫未将 `/gpu-inventory`、`/gpu-specs` 与 `/quotas` 识别为 platform 路径，平台令牌会在到达业务处理前被拒绝。
- ANI OpenAPI 已声明 `PATCH /gpu-inventory/{device_id}` 维护状态接口，但当前 ani-gateway 未注册对应路由；前端只展示 `maintenance` 状态，不提供会产生假成功的维护写操作。
- `ops-pool/index.tsx` 以及若干租户管理路由超过建议规模，应按独立表格、弹窗和业务流程逐步拆分。
- 部分业务状态仍集中在 Provider 与模型文件中；接入真实数据时需明确服务端状态、页面状态和演示状态的边界。
- `src/features/` 已不再作为目标目录；遗留内容应在相关功能调整中迁移到 `src/components/<scope>/`，不得继续扩展。
- 当前静态页面已覆盖产品原型中的全部 BOSS 导航入口；接入真实数据、写操作和跨页闭环时仍需逐项查询 ANI 后端契约，不得将演示数据作为接口依据。
