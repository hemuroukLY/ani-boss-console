# ANI BOSS Console 当前状态

> 本文件只记录当前功能状态、缺口和最近变更；开发规则以 `AGENTS.md` 及其引用的专项文档为准，产品与接口事实仍以对应 GitNexus 索引为准。

## 模块状态

### 平台运营总览

- 运营总览：运营指标、告警摘要与待处理事项。
- 资源池与容量态势：读取 ANI 平台容量接口，展示整平台默认区域、GPU、Ready GPU 节点、CPU/内存 allocatable 总量和可用租户汇总；数据源部分降级时根据 `dev_profile` 提示数据可能不完整。
- GPU 资源池态势：GPU 设备、使用率与状态展示。
- AI 服务运营态势：推理服务指标、趋势和异常服务。
- 知识库运营态势：知识库规模、查询趋势和索引状态。
- 平台告警与待处理：平台告警列表及演示处置状态。

### 租户管理

- 租户列表与租户详情。
- 配额策略列表与详情。
- 租户管理员列表与详情，以及邀请、角色和密码相关弹窗。
- 租户计费与用量列表、详情和账务记录。
- 租户生命周期、身份安全、配额使用与操作历史等详情区域。

### 资源池与基础设施

- 平台资源池总览。
- GPU 资源池管理：按 `产品原型-9.08 v2` 保留租户分配台账、设备列表、调度队列和事件四个 Tab，并将显卡切分改为设备列表卡片上的“集群切分配置”。配置仅面向所有空闲整卡，支持 2、4、8 等分和每份显存预览；提交后按任务接口恢复、轮询并展示已应用、跳过和失败节点，完成态仅保留任务结果和关闭操作，不再进入旧 GPU 调度规格弹窗。设备行不再提供单卡切分操作，指定物理卡分配和维护仍未接入。页面同时展示 ANI 返回的库存、占用汇总、租户 GPU 配额及聚合预留；全租户 `/quotas` 内嵌 `gpu_reservation`，台账展示资源预留、已用、处理中和可创建数量，并支持配额上限与资源预留调整及写后刷新。平台调度队列和事件仍因缺少匹配接口展示空态。
- 节点状态，位于资源池菜单下，包括区域、资源池、健康状态和关键字筛选。
- 存储基础设施，位于基础设施菜单下，展示块、对象、文件和向量存储后端的健康与容量状态、StorageClass 运营和最近平台事件。
- 租户存储配额，位于基础设施菜单下，顶部保留汇总指标，下方由租户热度 TopN、租户存储配额和最近事件三个板块组成。
- 网络基础设施，位于基础设施菜单下，展示 SDN 控制器、出口网关、IPAM、网络组件和 IP 地址池运行状态。
- 镜像仓库运维，位于资源池与基础设施菜单下，包括租户镜像配额、漏洞扫描和垃圾回收三个静态页面；支持配额状态、镜像风险、用途和关键字筛选，后台操作以禁用态保留。

### 运维与可观测

- 平台健康：读取 ANI 服务、基础依赖和平台组件三组运行状态、资源类型、版本及就绪副本；服务观测未知单独标记为“观测异常”，不计为组件故障，并支持按组件进入实时日志。
- GPU 监控、推理监控和知识库监控：使用统一监控骨架展示领域指标、趋势图和当前关注项。
- 组件指标：支持切换平台组件，展示 P99、错误率、就绪副本、请求量和依赖探测结果。
- 日志与 Trace：日志页按单组件接入 SSE 最近日志回放和实时增量，支持自动重连、回放去重、级别与关键字筛选；Trace 仍使用调用链样本切换、瀑布图和耗时排行。
- 告警规则、运维 Skills、任务历史和故障处理：原型未接入 Store，当前统一保留优先级与未接入说明，不补造列表、筛选或操作数据。

### 平台计量与结算

- 计量总览：保留 GPU-Hours、CPU-Hours、Memory、Storage、Tokens 和 KB Queries 六个原型页签；GPU、CPU 和 Memory 页签读取 ANI 平台计量数据，按本月、上月同期和日粒度展示合计、环比、峰值日、近 7 日趋势与租户 ID 用量排行，并支持从排行按天或按小时下钻单租户明细。秒与 GiB·秒统一换算为对应 Hours 单位，并根据 `dev_profile` 标识开发 Provider。接口未返回租户名称、区域和配额汇总，因此不展示对应模拟字段；Storage、Tokens、KB Queries 与导出保持未接入说明或禁用态。
- 原型菜单备注写有“七类指标”，但页面线框实际只定义上述六个页签；当前实现以可运行线框为准，待产品口径澄清后再补充。

### 安全审计与合规

- 平台审计日志、API Key 审计、推理调用审计和合规导出与取证：原型均未接入 Store，当前统一使用占位页，不补造审计记录、筛选项或取证向导。

### 平台设置

- 平台登录：接入 ANI 平台管理员账密登录、登录态持久化、Bearer 请求头、401 单飞刷新、受保护路由和退出吊销；开发环境可显式跳过登录以配合 ANI 开发鉴权模式。
- 平台运营账号：展示管理端本地登录身份、角色、状态、MFA 和最近登录信息，支持角色、状态和关键字筛选以及只读详情；账号不属于租户，也不会同步为租户成员。
- 登录与 IdP、会话与安全策略：分别为 P1、P2 预留页，当前统一保留未接入 Store 占位，不展示推测性的配置结构或策略值。

### 平台集成与通知

- 运维 Webhook、企业通知集成和运营系统对接：原型未接入 Store，当前统一使用占位页，不补造订阅、渠道、投递或外部系统数据。

产品原型 `产品原型-9.08 v2` 中 BOSS 端导航入口均已形成对应静态路由；后续新增范围仍须先更新并查询产品原型。

## 当前可对接接口清单

> 核对日期：2026-09-10。以下是接入就绪度清单，不保存接口契约副本；字段、错误码和权限仍以 GitNexus 索引 `ANI` 中的 OpenAPI、网关路由和处理流程为准。

- `可直接对接`：路由与处理逻辑已存在，平台登录令牌的边界允许访问；仍需按 `dev_profile` 或依赖状态区分真实 Provider 与开发回退。
- `条件可对接`：主要契约可用，但只能覆盖页面部分区域，或依赖运行时 Provider、下游服务和数据落库。
- `已接入`、`部分已接入`、`已接入但受阻`：说明当前前端已经调用全部或部分接口，后缀同时标明是否仍有上线阻塞。
- `后端需先补齐`：只有契约、路由语义不匹配、平台令牌会被拒绝，或缺少页面所需的聚合接口。

## 当前缺口与整理重点

- 当前资源池与容量态势、平台组件状态与单组件实时日志、GPU 资源池管理和平台 GPU/CPU/内存计量已接入 ANI API；其余前端演示数据仍不能作为接口契约依据。未接入原因与后续顺序见 [未接入接口现状](./API-INTEGRATION-GAPS.md)。
- 接口接入以原型中的 GPU 端到端业务流程为唯一 P0 主线：平台资源确认与租户额度配置、Console 租户自查与实例创建、资源占用与计量回流必须连续调通。产品经理的演示路径仅作为联调验收顺序，不是页面功能；其他已就绪接口在 GPU 流程完成后再安排。
- 管理端已接入平台账密登录与身份会话；Vite 开发服务器通过 `VITE_API_PROXY_TARGET` 配置 `/api` 转发，`.env.development` 当前连接 `http://10.10.1.66:30083`，未配置时回退到 `http://127.0.0.1:8080`。本地 `ANI_AUTH_MODE=dev` 可使用开发跳过登录；生产部署仍需在 Web Server 或网关配置同源 `/api` 转发。ANI legacy scope 已允许 platform 身份访问 `/gpu-inventory*`、`/gpu-specs*` 和 `/gpu-scheduling*`，并将跨租户 `/quotas` 精确限定为 platform；`/auth/logout`、`/notifications/email/*` 和通用 `/observability/*` 仍未进入 platform 可访问边界，`/metering/usage/platform` 则使用 generated platform policy。
- ANI OpenAPI 已声明 `PATCH /gpu-inventory/{device_id}` 维护状态接口，但当前 ani-gateway 未注册对应路由；前端只展示 `maintenance` 状态，不提供会产生假成功的维护写操作。
- GPU 集群切分以临时补充文档为过渡契约：切分接口明确支持 2、4、8 等分，忙碌、离线和已切分节点由任务结果标记为跳过；ANI 主索引尚未包含切分路由，测试环境恢复后需优先完成端到端联调。
- `ops-pool/index.tsx` 以及若干租户管理路由超过建议规模，应按独立表格、弹窗和业务流程逐步拆分。
- 部分业务状态仍集中在 Provider 与模型文件中；接入真实数据时需明确服务端状态、页面状态和演示状态的边界。
- `src/features/` 已不再作为目标目录；遗留内容应在相关功能调整中迁移到 `src/components/<scope>/`，不得继续扩展。
- 当前静态页面已覆盖产品原型中的全部 BOSS 导航入口；接入真实数据、写操作和跨页闭环时仍需逐项查询 ANI 后端契约，不得将演示数据作为接口依据。
