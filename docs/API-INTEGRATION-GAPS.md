# ANI BOSS Console 未接入接口现状

> 核对日期：2026-09-09。本文件记录前端尚未接入或尚不能生产可用的能力及其主要原因，不保存接口契约副本；接口字段、权限和行为以 GitNexus 索引 `ANI` 为准，尚未合入主索引的过渡能力以 `ani-boss-console对接文档补充` 为临时补充。

## 接入目标

接口接入不再按“哪个接口更容易接”横向推进，而是优先打通原型中的 GPU 端到端业务流程。原型中产品经理用于讲解和验收的路径只用于确定联调顺序，不是名为“GPU 演示”的页面功能或交互入口。

P0 完成标准是：平台管理员能够查看 GPU 资源、配置租户可用额度，租户能够在 Console 查看额度并创建 GPU 实例，创建结果能够回流到资源占用、监控和计量。任一环节仍依赖前端静态数据、开发鉴权旁路或假成功，都不能算流程调通。

## 分类口径

- **排期未实施**：后端路由、处理器和平台身份边界已经满足当前页面能力，主要剩余工作是前端接入与页面状态替换。
- **接口覆盖不足**：已有接口只能支持页面的一部分，接入时必须明确保留的缺口，不能用前端数据补成完整能力。
- **权限或网关阻塞**：处理器存在，但平台令牌在到达业务逻辑前会被 scope 守卫拒绝，当前只能在开发鉴权旁路下工作。
- **接口未准备好**：缺少平台聚合接口、路由未注册，或现有接口属于租户语义而非 BOSS 平台语义。
- **运行环境依赖**：契约已具备，但真实数据依赖 Provider、Prometheus、下游服务或平台身份签发配置。
- **产品排期或预留**：原型明确为后续优先级或占位能力，当前不应提前推测配置结构。

## 已接入基线

- 平台账密登录、令牌持久化、Bearer 请求和 401 单飞刷新。
- GPU 库存、占用、租户 GPU 配额及聚合预留已在 GPU 资源池页呈现；全租户 `/quotas` 内嵌 `gpu_reservation`，前端直接读取 `allocated_gpu_count`、`used`、`reserved` 和 `available`，不再逐租户发起补充查询，并通过已有单租户预留接口支持调整。ANI 已修复 P0 GPU legacy 路径的 platform scope，`30083` 新网关请求此前已验证正常。按 `产品原型-9.08 v2` 和临时补充文档，集群切分配置已接入 2、4、8 等分及异步任务恢复/轮询；完成态仅展示任务结果，不再进入旧 GPU 调度规格弹窗。本次测试网关无法连通，仍缺真实提交和写后回读证据。
- 平台容量：资源池与容量态势页已读取区域、GPU、节点、CPU、内存和租户汇总，并展示 `dev_profile` 数据来源。
- 平台服务健康：平台健康页已读取七个 ANI 核心服务的抓取状态、观测/可达副本、版本和最近采集时间；监控源未配置或不可用时展示真实 503 错误，不回退静态数据。
- 平台 GPU 计量：计量总览 GPU 页签已按本月、上月同期和日粒度读取平台计量接口，换算 GPU-Hours 并展示租户用量、环比、峰值日、近 7 日趋势与 `dev_profile` 数据来源。

## GPU 流程就绪度

| 阶段 | 目标能力 | 当前状态 | P0 剩余工作 |
|------|----------|----------|-------------|
| 平台身份 | 平台管理员登录后访问 GPU 管理能力 | 登录与令牌刷新已接入；GPU legacy platform scope 已修复，`30083` 请求已验证正常 | 继续覆盖完整读取、写操作与写后回读 |
| 资源确认 | 查看 GPU 库存、占用和平台调度队列 | 库存与占用已接入，设备表已按原型展示节点/卡、型号、切分、状态、归属和操作；切分列已接入 `shares=1/2/4/8`；平台调度队列无对应接口 | 前端将 `shares=1` 展示为整卡，将 2、4、8 展示为对应 vGPU 份数。ANI 库存状态仍只有 `available`、`in_use`、`fault`，缺少“已预留给租户”设备状态、切分后的算力占比和设备级权威归属；现有 `tenant_id`、`instance_id` 按节点 Running Pod 数量和卡索引顺序推算，并未持久化实际设备索引。维护写接口也未注册，因此操作列保持 `-`；继续验证非 dev 环境库存与占用数据源、错误态和刷新结果 |
| 资源配置 | 在集群配置 GPU 等分规则，并设置租户 GPU 配额和聚合预留 | 集群切分已按临时补充接入 2、4、8 等分与任务进度；GPU 配额及聚合预留的读取与调整已接入 | 在部署环境验证切分提交、跳过/失败节点、任务恢复和写后库存，并验证 `/quotas` 内嵌预留数据及单租户预留调整的写后回读。指定物理卡分配仍待 ANI 提供接口 |
| 租户确认 | Console 查看自身配额、预留和规格可用性 | BOSS 仓库不包含 Console；ANI 有租户侧查询与规格预检能力 | 与 `ani-console` 联调 tenant scope 下的配额、预留和规格可用性，不由 BOSS 代替租户调用 |
| 实例创建 | 租户提交 GPU 实例并得到真实准入结果 | 尚未在本项目形成跨系统验收证据 | 打通实例创建、配额不足和库存不足路径，确认拒绝原因来自 ANI |
| 结果回流 | 实例状态反映到 GPU 占用、监控和平台计量 | 占用查询与平台 GPU 计量已接；GPU 监控仍缺平台聚合 | 验证实例创建后的占用和计量变化，并补齐平台 GPU 监控所需接口 |

## 一、排期未实施

这些项目已有可用处理器，但只有能推进 GPU 主流程的能力进入 P0；其余按流程完成后的收益排序。

| 优先级 | 模块 | 未接入能力 | 当前原因 | 下一步 |
|--------|------|------------|----------|--------|
| P0 | GPU 流程 | 单租户 GPU 配额与聚合预留的读取、调整和写后回读 | 管理端接口、GPU 资源池页、platform scope 和 `30083` 请求已具备，但还缺完整读写联调证据 | 在 `30083` 覆盖成功、配额下限、预留冲突和刷新回读 |
| P1 | 租户管理 | 配额策略列表、详情、创建、编辑、发布、禁用、绑定与历史 | 接口已就绪，页面仍使用前端 Provider 和模型 | GPU 流程调通后建立租户套餐 API 层，先替换列表与详情读取，再接写操作和写后刷新 |
| P1 | 租户详情 | 单租户通用配额与 GPU 聚合预留 | 管理端路径可用，当前只在 GPU 资源池页复用部分能力 | 复用 GPU 流程的数据层，将权威额度同步展示到租户详情 |
| P1 | 租户管理 | 租户列表与基础详情 | 可读取 ID、名称、展示名、状态、套餐和时间字段，但不能支持完整管理流程 | 先替换只读基础信息；创建、编辑、生命周期和身份安全继续保持未接入 |
| P2 | 租户管理 | 跨租户管理员列表、详情、邀请、重发、角色、密码、启停、删除与历史 | 接口已就绪，但不影响 GPU 流程调通 | GPU 主流程完成后，再按危险等级接入写操作 |

## 二、接口覆盖不足

| 模块 | 能覆盖的部分 | 尚缺能力 | 处理原则 |
|------|--------------|----------|----------|
| 平台容量 | 区域、GPU、节点、CPU、内存、租户汇总 | 资源池明细、容量趋势和平台事件 | 容量态势页已接支持字段；平台资源池总览的明细和事件暂不替换 |
| 平台健康 | 七个 ANI 核心服务的 Prometheus 抓取可达性、版本和最近采集时间 | P99、错误率、依赖拓扑、数据面组件 | 只展示接口返回字段，并明确“部分覆盖” |
| 租户存储配额 | 单租户通用配额中的 `storage_gb` | 对象数、NFS、向量、IOPS、带宽、TopN、扩容申请和事件 | 不用单一额度推导完整存储运营视图 |
| 平台计量 | GPU、CPU、内存和 Tokens 用量 | Storage、KB Queries、价格、账单、结算、发票和导出 | GPU 已接，并由前端按接口明细计算环比和峰值日；CPU、内存和 Tokens 待核对页面计量口径，缺失页签和结算区保持说明态 |
| 租户基础详情 | ID、名称、展示名、状态、套餐和创建更新时间 | 联系信息、生命周期、身份安全和全量操作历史 | 仅替换有权威字段的区域，不合并前端演示字段 |
| GPU 分配 | 集群级空闲整卡等分、租户聚合配额与预留 | 指定物理卡绑定、单卡切分和测试库存 | 集群切分按新原型配置节点规则；保持聚合语义，不把预留解释为物理卡分配，也不恢复旧版单卡切分入口 |

## 三、权限或网关阻塞

| 模块 | 受阻能力 | 阻塞原因 | 解除条件 |
|------|----------|----------|----------|
| 平台设置 | 退出吊销 | `/auth/logout` 仍走 legacy 权限路径 | 将退出路由纳入平台身份可访问边界 |
| 平台通知 | SMTP、收件人、订阅和测试发送 | legacy scope 不接受平台令牌；当前 Store 还是本地内存实现 | 修复平台权限并接入可持久化 Store |
| 运维与可观测 | 通用 PromQL 查询与告警规则 | 当前接口为租户语义，legacy 路径也不接受平台令牌 | 提供平台查询边界或明确新增 BOSS 专用聚合接口 |

## 四、接口未准备好或语义不匹配

| 模块 | 未接入能力 | 主要缺口 |
|------|------------|----------|
| 平台运营总览 | AI 服务运营态势、知识库运营态势、平台告警与待处理 | 现有服务接口均为租户资源管理，没有跨租户规模、趋势、异常和告警聚合 |
| 租户管理 | 创建、编辑、生命周期、身份安全和完整操作历史 | 缺少匹配的 BOSS 管理接口；套餐和管理员历史不能替代租户全量历史 |
| GPU 资源池（P0 缺口） | 设备维护、指定卡分配、平台调度队列、资源池事件及集群切分联调 | 维护接口只有 OpenAPI 声明但网关未注册；指定卡分配没有匹配实现；现有队列强制租户上下文。集群切分已按临时补充接入，但 POST 路由尚未进入 ANI 主索引，需在部署环境验证 |
| 节点状态 | 节点健康、标签、污点和心跳清单 | 现有集群接口是租户/集群管理面，不是 BOSS 节点运营接口 |
| 存储基础设施 | 后端健康、容量、StorageClass 和平台事件 | 现有存储接口是租户资源 CRUD，缺少平台聚合 |
| 网络基础设施 | SDN、出口网关、IPAM、组件健康和平台 IP 池 | 现有网络接口是租户网络 CRUD，语义不匹配 |
| 镜像仓库运维 | 跨租户配额、漏洞运营、垃圾回收和平台任务 | 现有 registry 接口面向租户使用，不提供平台运营视图 |
| 运维与可观测 | GPU/推理/知识库指标、平台日志、Trace、平台任务和故障处理 | 缺少平台级聚合查询、检索和处置接口 |
| 平台计量与结算 | 价格、账单、结算、发票和导出任务 | 后端没有匹配接口 |
| 安全审计与合规 | 平台审计、API Key 审计、推理调用审计和合规取证 | 现有 API Key 接口属于当前租户管理，不是跨租户审计 |
| 平台设置 | 平台运营账号 | OpenAPI 有声明，但网关没有注册对应处理器 |
| 平台集成 | 平台运维 Webhook、企业通知渠道和运营系统对接 | 现有 Webhook 是租户语义；其余缺少平台配置、订阅和投递接口 |

## 接入顺序

1. **P0-1 平台侧可用**：ANI 已解除 GPU 库存、占用、调度规格和全租户配额的 platform scope 阻塞；继续使用非 dev 平台身份在 `30083` 验证读取、调整、错误提示与写后回读。
2. **P0-2 验证集群切分**：在部署环境覆盖 2、4、8 等分、幂等重试、忙碌/离线/已切分节点跳过、失败重试、任务恢复和完成结果；指定卡分配、维护和平台调度队列仍按后端边界单独补齐。
3. **P0-3 打通租户侧交接**：与 `ani-console` 联调租户自身配额、预留、规格可用性和 GPU 实例创建，覆盖正常创建、配额不足和库存不足。
4. **P0-4 验证结果回流**：平台 GPU 用量已接入；继续确认实例创建后库存占用和计量均发生真实变化，GPU 监控缺少的平台聚合接口列为本流程阻塞项。
5. **P0 验收**：按上述跨角色业务顺序逐步操作，所有数据和结果来自 ANI；产品经理的演示路径只作为验收脚本，不实现页面向导、快捷入口或模拟动作。
6. **GPU 流程完成后**：再接租户套餐、租户基础信息、租户管理员及其他平台模块；接口就绪度只决定同一阶段内的先后，不再改变 GPU 主线优先级。
7. 每完成一个 GPU 阶段，同步更新本文件和 [当前状态与开发记录](./PROJECT-STATUS.md)，记录联调环境、已验证角色与仍受阻的环节。
